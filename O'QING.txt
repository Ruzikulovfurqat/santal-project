ИШЛАБ ЧИҚАРИШ БОШҚАРУВ МАРКАЗИ — СЕРВЕР (DOCKER + POSTGRESQL) ВЕРСИЯСИ
=====================================================================

Дастур, Телеграм бот ва PostgreSQL базаси битта серверда Docker орқали
бирга ишлайди. Бир хил Wi-Fi/LAN тармоғидаги бошқа компьютерлардан ҳам
кириш мумкин.


1) ТАЛАБ ҚИЛИНАДИГАН НАРСА
---------------------------
Серверда Docker (Docker Compose билан) ва make ўрнатилган бўлиши керак.
Текшириш:
    docker compose version


2) ИШГА ТУШИРИШ
----------------
Лойиҳа папкасида:

    cp .env.example .env

.env файлини очиб, камида POSTGRES_PASSWORD'ни (база пароли) ва керак
бўлса BOT_TOKEN'ни (Телеграм бот токени) ёзинг. Кейин:

    make up

Дастур шу манзилда очилади:

    http://<сервер-IP>:8642     (масалан http://192.168.1.25:8642)

BOT_TOKEN бўш бўлса, фақат дастур ишлайди (бот ишга туширилмайди).

Бот дастурнинг ўзида ишлайди. .env'да WEBHOOK_URL бўш бўлса — polling
(серверни интернетга очиш, домен ёки SSL шарт эмас). WEBHOOK_URL=https://...
бўлса — webhook: у алоҳида портда (WEBHOOK_PUBLIC_PORT) ишлайди ва у ерда фақат
бот бор; дастурнинг ўзи (8642-порт) интернетга очилмаслиги керак.

Базадаги жадваллар ва уларнинг янгиланишлари (migrations папкаси) ҳар ишга
тушишда автоматик қўлланади — қўлда ҳеч нарса қилиш шарт эмас.
Ботдаги маҳсулот категориялари дастурнинг «Категориялар» бўлимидан
олинади — у ерга қўшилган категория ботда ҳам кўринади.

3) БОШҚА КОМПЬЮТЕРЛАРДАН КИРИШ
--------------------------------
Шарт: барча компьютерлар БИР ХИЛ Wi-Fi ёки локал тармоқда (LAN) бўлиши
керак (масалан, битта роутерга уланган).

Ҳар қандай бошқа компьютер (ёки телефон/планшет) браузерида сервер
кўрсатган иккинчи манзилни очади, масалан:

    http://192.168.1.25:8642

Шунда у ҳам худди сервер компьютери каби тизимга киради ва БИР ХИЛ
маълумотларни кўради/ўзгартиради (буюртма, омбор, касса ва ҳ.к. — барчаси
реал вақтда, 1-2 сония ичида барча компьютерларда янгиланади).

Агар бошқа компьютер очолмаса:
  - Иккала компьютер ҳам бир хил тармоқдами — текширинг.
  - Сервер компьютерининг Firewall (файрвол) дастури 8642-портни
    блоклаётган бўлиши мумкин — унга рухсат беринг ёки уни вақтинча
    ўчириб кўринг.


4) АДМИН ҲУҚУҚИ
-----------------
Тизимнинг ўзида "Админ" тугмаси бор — уни босганда PIN сўралади.
Стандарт PIN: 0000

PIN'ни билган ҲАР ҚАНДАЙ компьютер (сервер бўладими, бошқа компьютер
бўладими — фарқи йўқ) "Админ" тугмаси орқали шу ҳуқуққа эга бўлади.
PIN'ни "Омборлар → Бошқарув" бўлимидан хоҳлаганча ўзгартиришингиз мумкин
— шундан кейин фақат янги PIN'ни билганлар админ бўла олади.

ДИҚҚАТ: бу тармоқ ичидаги оддий парол ҳимояси — ташқи интернетдан ҳимоя
эмас. Шунинг учун бу серверни фақат ишонган локал тармоғингизда (офис,
цех Wi-Fi'и) ишлатинг, уни интернетга очиқ қилиб қўйманг.



5) МАЪЛУМОТЛАР ҚАЕРДА САҚЛАНАДИ
---------------------------------
Барча ёзувлар (буюртмалар, омбор, касса, ходимлар, бот диллерлари ва
прайслари — ҳаммаси) PostgreSQL базасида сақланади. База Docker'нинг
"santal_pgdata" номли volume'ида туради — контейнерлар тўхтатилса ёки
янгиланса ҳам маълумот йўқолмайди.

Акт файллари (сканлар) аввалгидек "baza/uploads" папкасида.

Эски версиядан ўтилаётган бўлса: baza/data.json (ва ботнинг эски
bot/bot.db файли) биринчи ишга тушишда, база бўш бўлса, PostgreSQL'га
автоматик кўчирилади. Файлларнинг ўзига тегилмайди.

МУҲИМ — ЗАХИРА НУСХА (backup): вақти-вақти билан (масалан, ҳафтасига бир
марта)

    make backup

буйруғини беринг — "backups" папкасида база дампи ва акт файллари архиви
пайдо бўлади. Уларни бошқа жойга (флешка, бошқа диск) нусхалаб қўйинг.


6) СЕРВЕРНИ ТЎХТАТИШ ВА ҚАЙТА ИШГА ТУШИРИШ
---------------------------------------------
    make down      — тўхтатиш (маълумотлар сақланиб қолади)
    make up        — қайта ишга тушириш (янгиланган кодни ҳам йиғади)
    make logs      — логларни кўриш
    make help      — барча буйруқлар

Сервер компьютери қайта ёқилганда контейнерлар ўзи ишга тушади (Docker
хизмати ёқилган бўлса).
